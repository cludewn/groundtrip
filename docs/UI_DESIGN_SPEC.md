# GroundTrip UIデザイン共有仕様（レビュー草案）

更新日：2026-11-07  
状態：**チームレビュー待ち**。この文書は未承認の提案を含む。全体を「確定デザイン」とみなさない。

## 1. 目的と正本

GroundTripの「AIの提案を、人間が根拠で選ぶ（Own the Why）」を、旅程表示から修正・承認・振り返りまで一貫した操作にする。

- プロダクトの不変条件：`docs/PRODUCT_AND_ARCHITECTURE.md`、`docs/UX_DESIGN_PRINCIPLES.md`、`docs/DOMAIN_CONTRACTS.md`が優先する。
- **確定済み方針**：旅程一覧は縦の路線図型を主軸にする。重要情報を確認し、特定の予定だけを修正する。
- **デザイン出発点**：共有された「案A（路線図型）」のモック、PR #20の実装。画像・モック中の京都、時刻、施設、料金、予約は例示であり実データではない。
- **チーム承認待ちの提案**：種類ごとのチケット表現、予約・乗車券の意匠、チケットの完了操作、配色・書体・画面遷移の細部。本書の「提案」はマージだけで自動的に確定しない。
- **Figma**：共有デザインファイルと承認済みフレームのURLは、作成後この節に追記する。未登録の間はモックと既存実装を参照し、具体的な色や画面構成を独断で確定しない。

## 2. 表示の基本構造

| 表示対象 | 提案する表現 | 意図・注意 |
| --- | --- | --- |
| 観光・散策など通常のStop | 路線図の標準ノード | 予定全体の時系列・優先度を保つ |
| 食事・カフェのStop | 路線図に接続したフードチケット風カード | 楽しさとタップ対象の明確化。正式な予約券には見せない |
| 利用者が固定したStop | ノード・カードにロック状態を重ねる | **固定 = 予約済みではない**。固定状態だけを表す |
| 徒歩・通常の公共交通など移動 | Stop間の路線区間・所要時間欄 | 原則、移動のたびにチケットを増やさない |
| 時刻が厳密な新幹線・特急等 | 乗車券風の強調表示を検討 | 現段階では任意案。時刻・予約・購入を推測しない |
| AIが確認を推奨する予定 | 状態ラベルで要注意を示す | 種別と照合・承認状態を混ぜない |

チケットは**路線図上のStop/区間の表現バリエーション**であり、画面上の別の旅程や決済商品ではない。全Stopをチケットにはしない。表示のためにドメインモデルの意味を変えない。

### 公共交通に関する現実的制約

- 現在の#7 Routesアダプターは徒歩・車の経路を扱い、公共交通（TRANSIT）には未対応。**電車・バスの経路・運行時刻・乗車時間を検証済みと表示しない**。
- Geminiから交通に関する提案があっても、未照合の情報として区別する。根拠のない運賃・所要時間・発車時刻を補完しない。
- 「予定を固定した」「予約している」「乗車券を購入した」は異なる情報。予約・購入状況の裏付けがなければ断定しない。
- 交通の独立したStopや予約状態を型へ追加するかは、#7/#9と共通契約の変更として別途判断する。

## 3. 状態は別の軸に分離する

見た目（ノード/チケット）とは独立して、次の情報を扱う。

| 軸 | 既存の根拠・表現 | 禁止する誤解 |
| --- | --- | --- |
| 予定種別 | 観光・食事・移動などの表示上の分類（型追加は未決定） | 見た目だけから実際の予約状態を決定しない |
| 固定状態 | `Stop.isFixed` | 固定しただけで購入・予約済みにならない |
| 情報照合 | `consistent` / `conflicting` / `unverifiable`、未照合は`evidence: []` | 情報源との整合を現実の絶対的正しさと表示しない |
| 制約検証 | `not_checked` / `satisfied` / `violated` / `unknown` | 情報源との整合と実行可能性を混同しない |
| 本人承認 | `pending` / `approved` / `rejected` | AI提案・画面プレビューを承認済みにしない |
| 予約・購入状況 | 現行ドメインでは独立した正本がない | 根拠のない「予約済み」や購入済み風表示は禁止 |
| 現地完了 | チケット消費案は**未採用**、状態・時刻モデルは未定義 | UI操作だけで本人承認や後続変更を確定しない |

照合状態は**文言と形**で区別し、色のみで伝えない。根拠の出典・照合日時・対象日時も閲覧可能にする。「未照合」「確認できない」「矛盾あり」を別々に示す。

## 4. 重要な操作フローと画面

### A. 旅程作成・一覧

1. 行き先・日付・希望条件から旅程を生成する（#16、#6）。
2. AIの結果は**提案**として表示し、根拠照合やユーザー承認と混同しない。
3. 路線図でStop順、予定開始時刻、見積滞在時間、移動・固定の情報を確認する（#8）。
4. 必要なStopだけを選び、修正へ進む（#9）。

### B. 部分修正・比較・承認（最重要画面）

1. 変更対象と理由を明示。固定Stopは勝手に解除・変更しない。
2. 変更候補をプレビューし、**変更前→変更後**の地点・時刻・移動・固定予定への影響を比較する。根拠が無い金額・時間は算出しない。
3. 候補の照合状態と決定論的な制約検証を区別。成立しない候補は採用可能と表示しない。
4. 明示的な「採用する／キャンセル」で決定。承認前や失敗時は元のTripを保持する。
5. モックの「A/B/C」は候補ラベル。Aだけを自動的に唯一の実行可能候補として固定しない。

### C. 現地トラブル・振り返り・次回反映

- 現地の閉店・遅延は、実際の報告とデモ用の模擬報告を区別し、Bの部分修正フローを再利用する（#11）。
- 振り返りでは候補を本人が編集・承認・却下し、承認済み学びだけを保存する（#12）。
- 次回旅程では適用した学びと反映先を示し、前後比較の対象を明示する。モデル自体の再学習とは表現しない（#13）。

## 5. チケットを「使う／切る」操作（未確定・設計検討）

食事などの終了時刻をAIが**確定できない**という指摘は妥当。ただし、滞在時間の**推定値**を提案すること自体は可能。予定上の見積終了と実際の終了を区別する。

提案する将来の操作：
1. 「食事を終えた」など、明確なボタンで完了を報告する。アニメーションだけを唯一の入力方法にしない。
2. 実際の完了時刻を確定するため、ユーザー操作時刻と任意の修正を区別する。
3. 影響を表示。後続の予定変更が必要なら部分修正・本人承認を経由し、固定予定を保護する。

**現時点ではUI演出・状態更新・自動時刻調整を実装済み仕様と扱わない。** 既存の`Trip`/`Stop`に実績時刻・完了状態はないため、機能化する場合は独立したデータ契約とテストが必要。既存6機能をこの演出で置き換えない。

## 6. ビジュアル・コンポーネントの作成ルール（提案）

- モバイル縦画面を主対象とし、390px前後で横スクロール・操作不能・過密表示がないか確認する。
- 路線図の標準ノード、フードチケット、ロック表示、照合ラベル、候補比較シートを**少数の再利用コンポーネント**として設計する。
- 配色は既存モックの橙・黒・オフホワイト系を**検討の出発点**にする。カラーコード、フォント、余白、サイズ、影、アニメーションはFigmaの承認済みフレームができるまで未確定。
- 重要な根拠、時間制約、固定予定、主要操作は見えやすく。WCAGの基本的なコントラスト・フォーカス・タップ領域を確認する。
- Maps Platform由来のデータを表示する場合は必要な帰属表示を行う。
- 予約券・入場券と紛らわしいQRコード、実在の券面、利用権を示唆する文言を無根拠に使わない。

## 7. Figmaで確定・共有する範囲

1. **路線図・チケットのルール**：通常Stop、食事、固定、未照合・矛盾、移動区間。
2. **部分修正**：候補・差分・制約・根拠・承認前／後・失敗。
3. **現地と振り返り**：模擬報告、完了時の状態、学びの編集・承認、次回反映。
4. 上記の通常・警告・失敗状態と主要CTAの配置。

Figmaで承認したフレームのURL、更新日、承認者をこの文書へ追記する。Figmaは**視覚仕様の正本**、本書は**操作と状態の正本**とする。明示的に承認されていないFigmaの試作は参照案としてのみ扱う。

## 8. エージェント・実装担当への共有手順

- UI作業開始前に`AGENTS.md`、本書、`docs/UX_DESIGN_PRINCIPLES.md`、該当Issueと最新の承認済みFigmaを確認する。
- 本書の**確定済み方針**だけを拘束条件とし、**提案・未確定**は実装前にチームで決める。新しい共通型・保存対象・API仕様を見た目の都合だけで独断変更しない。
- 共通UI仕様更新はGitHub PR経由で合意・マージする。メンバーはそれぞれ最新`main`を取り込み、進行中のCodex等にも**再読を明示**する（既存エージェントは自動同期されない）。
- Figmaに直接接続できないメンバーには、承認済み画面の書き出しと本書を渡す。Figma接続自体は各自の権限・環境で設定する。
